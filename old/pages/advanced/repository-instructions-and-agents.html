Repository Instructions and Agents

Do not rely on repeated chat corrections when the repository can carry durable instructions that guide every AI-assisted change.

Expertise: Advanced Audience: Repository owners and agent users Use when: AI needs durable project context Version: 1.0

Who this is for

This guide is for teams that want AI agents to respect repository structure, conventions, ownership, validation, and security rules across repeated work.

What you will learn

  • Which repo files help AI work safely.
  • What durable instructions should contain.
  • When repository guidance must be updated.

Useful instruction files

AGENTS.md

Agent behavior rules, scope boundaries, validation, and commit expectations.

CODEX.md

Repository map, file purpose, versions, status, and ownership notes.

README.md

Human-facing setup, project purpose, and contribution basics.

PLAN.md

Phase plan, acceptance criteria, rollout, rollback, and stop points.

Focused instructions

Module-specific conventions, validation commands, or security rules.

Version tracking

Visible versions and map updates keep documentation aligned with reality.

Good use and risky use

Good use

Put durable rules in the repo: file ownership, coding conventions, validation commands, security rules, versioning, and update triggers.

Risky use

Correct the same agent mistake repeatedly in chat while leaving repository guidance stale, incomplete, or misleading.

Try this prompt

Use this before starting substantial repo work.

Read AGENTS.md, CODEX.md, README.md, and the relevant PLAN.md before editing. Summarize the applicable file ownership, conventions, validation commands, security rules, and versioning requirements. If the repository guidance is stale or missing for this change, identify the documentation update needed before implementation.

Review checklist

Durable rules: Are recurring instructions in files, not only in chat? Repository map: Does CODEX.md match actual files and versions? Conventions: Are style, validation, and ownership documented? Security: Are secrets, data, and tool boundaries explicit? Update trigger: Did the change require guidance updates?

Key takeaway

Repository instructions convert repeated corrections into durable controls. Good agent work starts with a repo that explains itself.
