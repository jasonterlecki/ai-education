Test-First AI Workflows

Tests are not paperwork. They are guardrails for delegated reasoning, especially when AI suggests implementation details.

Expertise: Advanced Audience: Developers, QA, analysts, leads Use when: AI helps design or change behavior Version: 1.0
Back to index Previous: Repository Instructions Next: Code Review with AI

Who this is for

This guide is for people using AI to define, implement, or review behavior where regressions, edge cases, and acceptance criteria matter.

What you will learn

  • How to define expected behavior before implementation.
  • Which tests AI can help draft.
  • Why tests alone do not prove safety.

What to define first

Expected behavior

Describe what should happen for normal inputs and states.

Edge cases

Include boundaries, nulls, races, timeouts, permissions, and unusual states.

Regression tests

Protect behavior that must not change.

Negative tests

Confirm invalid inputs, denied access, and failed dependencies behave safely.

Acceptance criteria

State what must be true before the work is done.

Smoke tests

Check the critical path after deployment or local changes.

Good use and risky use

Good use

Ask AI to propose tests from human-defined behavior, then review whether those tests would catch real failures and regressions.

Risky use

Let AI write implementation and tests together, then trust tests that only confirm the AI's own assumptions.

Try this prompt

Use this before implementation.

Given this intended behavior: [behavior]. Draft a test plan before implementation. Include normal cases, edge cases, regression cases, negative cases, acceptance criteria, and smoke tests. Identify where tests are not enough and what human review or operational validation is still needed.

Review checklist

Behavior: Are tests tied to explicit expected behavior? Regression: Do tests protect existing behavior? Negative paths: Are denial, failure, and malformed inputs covered? Independence: Would tests fail if the implementation is wrong? Limits: Are manual review, monitoring, or smoke tests still required?

Key takeaway

Test-first AI workflows make assumptions visible before implementation. They reduce, but do not eliminate, the need for accountable review.
