Checkpointed Execution Prompt

Use this to prevent context drift, uncontrolled scope expansion, and giant unreviewable diffs.

Expertise: Intermediate Also useful for: Advanced Category: Prompt Library Audience: AI coding-agent users Version: 1.0.1
Back to index Previous: Implementation Plan Next: Code Review

Who this is for

This prompt is for people directing AI coding agents or other implementation assistants through controlled, phase-by-phase work.

What you will learn

  • How checkpointed execution keeps AI-agent work reviewable.
  • How to require inspection, focused edits, validation, and reporting.
  • Why the agent must stop before the next phase.

When to use this

Use it when an implementation plan already exists and you want one focused phase completed, validated, reported, and stopped.

When not to use this

Do not use it to give an agent broad permission to continue across phases, refactor unrelated files, skip validation, or work without repository instructions.

Good use and risky use

Good use

Use this prompt to keep one phase small, validated, summarized, and ready for human review before continuing.

Risky use

Let an agent continue across phases, expand scope, skip validation, or create a large diff that reviewers cannot understand.

Copy-ready prompt template

One phase only 
Read:
- AGENTS.md
- CODEX.md
- PLAN.md

Implement Phase [NUMBER] only.

Before editing:
- inspect the existing codebase
- confirm where the change belongs
- identify affected files
- identify validation commands

Rules:
- do not proceed to the next phase
- do not perform unrelated refactors
- preserve existing behavior unless this phase explicitly changes it
- keep the diff focused
- stop when the phase is complete

When done, report:
- files changed
- validation commands run
- assumptions made
- risks
- follow-up items

Then stop and wait for explicit instruction.
Agent boundary: This prompt is for controlled execution after planning. It does not replace review, tests, approvals, rollback, or human ownership.

How to adapt it

Phase: Reference a specific plan phase and acceptance criteria. Files: Add file ownership boundaries when known. Validation: Name exact commands or manual checks. Risk: Add no-go areas and data-handling limits. Stop point: Require a report before continuing. Context: Include links to relevant plans, issues, or specs.

Review before using the output

Diff: Review actual changes, not only the summary. Scope: Confirm only the requested phase changed. Validation: Check commands and results. Behavior: Verify existing behavior was preserved unless intentionally changed. Risk: Identify follow-up review before continuing. Control: Give explicit instruction before the next phase.

Key takeaway

Checkpointed execution keeps AI-agent work small enough to understand, validate, roll back, and approve before continuing.
