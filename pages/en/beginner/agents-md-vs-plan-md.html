AGENTS.md vs. PLAN.md

These two files can look similar because both guide AI-assisted work. They do very different jobs. AGENTS.md is the project’s standing rulebook. PLAN.md is the work order for a specific change.

The shortest useful answer

AGENTS.md tells an AI agent how the project must be handled every time. PLAN.md tells the agent what to do for one specific piece of work.

AGENTS.md is governance. PLAN.md is execution. One is the constitution of the workspace. The other is today’s mission folder.

Why people mix them up

Both files can contain instructions, steps, warnings, and constraints. The difference is lifespan and authority. AGENTS.md should shape every session. PLAN.md should guide one change until that change is completed, replaced, archived, or discarded.

If a rule should still apply next month, it probably belongs in AGENTS.md. If it only exists to finish this task, it probably belongs in PLAN.md.
AGENTS.md

The standing rulebook

AGENTS.md is always present and always relevant. It tells AI tools how to behave in the project before they read the current task, edit files, run commands, or suggest changes.

  • Defines project-wide rules, boundaries, and governance.
  • Explains what agents must never do.
  • Sets validation, testing, review, and approval expectations.
  • Describes safe command patterns and forbidden shortcuts.
  • Should be durable, stable, and maintained over time.
PLAN.md

The temporary work order

PLAN.md exists to implement something. It breaks a specific change into action items, phases, assumptions, stop points, and validation checks. When the work is done, it can be archived, replaced, or removed.

  • Defines the goal and scope of one task or change set.
  • Lists action items, phases, checkpoints, and open questions.
  • Tracks what has been completed and what still needs review.
  • Should not override permanent safety or governance rules.
  • Can disappear once its job is finished.

Think lifespan first

When deciding where something belongs, ask how long the instruction should live. The calendar is often clearer than the vocabulary.

Permanent

Rules that keep applying

Use AGENTS.md for rules that should guide every future AI session: security boundaries, review gates, style rules, branch policy, validation expectations, and required human approval.

Temporary

Steps for this change

Use PLAN.md for the work in front of you: what to change, what order to do it in, what files are involved, what questions remain, and how to prove the change worked.

Bridge

Plans can reveal new rules

Sometimes a PLAN.md discovers a recurring rule. When that happens, move the durable lesson into AGENTS.md instead of leaving it buried in a completed plan.

Common examples

These are the kinds of lines that belong in each file. Keep the boring rails strong so the creative train can go faster.

AGENTS.md

Safety and permissions

“Never expose secrets. Do not commit credentials. Do not run destructive commands without explicit approval. Internal navigation links must not open in a new tab.”

AGENTS.md

Validation standards

“Run the relevant tests. Run git diff --check. Report changed files, validation results, and any skipped checks before handing work back.”

AGENTS.md

Project style rules

“Use Canadian French for pages under pages/fr/. Preserve filenames in English. Keep version metadata in governed HTML files.”

PLAN.md

Specific task steps

“Translate pages/en/beginner/example.html, update the matching checklist item, verify lang=fr-CA, and confirm navigation points to the expected French sibling pages.”

PLAN.md

Implementation phases

“Phase 1: create the page. Phase 2: update index links. Phase 3: validate HTML. Phase 4: summarize changes and open risks.”

PLAN.md

Open questions

“Confirm whether this page belongs under beginner or intermediate. Confirm whether the French version should link to a future translated next page.”

Good use and risky use

The danger is not having too many markdown files. The danger is making the wrong file authoritative.

Good use

Keep AGENTS.md short enough to obey and strong enough to matter. Use PLAN.md to make one piece of work concrete, reviewable, and easy to stop at checkpoints.

Risky use

Put permanent rules only in PLAN.md, leave completed plans pretending to be current, or let a task plan override project safety rules because it happens to be the newest file.

The lifecycle

AGENTS.md and PLAN.md move differently through time. One is a maintained compass. The other is a route card for a trip.

AGENTS.md

Create once

Start with project-wide rules, safe defaults, validation expectations, and human approval boundaries.

AGENTS.md

Maintain forever

Update it when the project’s durable rules change. Remove stale rules before they become decorative fossils.

PLAN.md

Create per effort

Write a plan when a change needs phases, risk notes, ordered steps, or explicit validation before implementation.

PLAN.md

Retire when done

Archive it if the history is useful. Discard it if it was only scaffolding. Carry durable lessons back into AGENTS.md.

Field guide takeaway: AGENTS.md is the durable governance file: always present, always relevant, and always used to shape agent behavior. PLAN.md is the temporary implementation file: useful for one change, one phase, or one work package, then archived or discarded once the job is done. If it governs the project, put it in AGENTS.md. If it drives today’s work, put it in PLAN.md.
