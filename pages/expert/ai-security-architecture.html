AI Security Architecture

AI security is not a chatbot setting. It is an architecture of access, data, tools, logs, and controls.

Expertise: Expert Audience: Security, platform, and governance leaders Use when: AI workflows access systems, data, or tools Version: 1.0

Who this is for

This guide is for security, platform, and architecture leaders designing controls for AI-enabled workflows and tool-using systems.

What you will learn

  • How identity, access, sandboxing, secrets, and connector permissions shape AI risk.
  • Why prompt injection and data loss require architecture-level controls.
  • How logging, audit trails, incident response, and vendor review fit together.

Strategic frame

AI security must cover what the model can see, what tools it can call, what credentials are exposed, what data can leave, what actions are logged, and how incidents are handled. The model is only one part of a larger security boundary.

Security architecture controls

Identity

Use named users, service identities, and clear ownership for AI actions.

Least privilege

Grant the minimum data, tool, connector, and environment access needed.

Sandboxing

Keep experimentation away from production systems and sensitive records.

Secrets isolation

Prevent prompts, logs, outputs, and tools from exposing credentials.

DLP

Apply data loss prevention to prompts, attachments, logs, and retrieval sources.

Incident response

Define response paths for leakage, unsafe actions, prompt injection, and vendor events.

Good use and risky use

Good use

Design AI workflows with least privilege, connector review, sandboxing, prompt injection defenses, logs, audit trails, vendor review, and escalation paths.

Risky use

Connect AI tools to broad data stores or production systems using shared credentials, weak logs, and no incident response plan.

Decision framework

AssistantApply approved-tool and data-use rules.
RetrievalAdd permissions, citations, and source governance.
Tool useAdd least privilege, approval gates, logs, and sandboxing.
Autonomous actionAdd monitoring, alerting, rollback, and executive risk acceptance.

Leadership questions

1. What identities, credentials, connectors, and tools does this AI workflow use? 2. Can prompt injection cause data exposure or unauthorized action? 3. Where are prompts, outputs, tool calls, and approvals logged? 4. What data loss prevention controls apply? 5. Who responds if the AI leaks data, takes unsafe action, or produces harmful output?

Governance checklist

Access: Review identity, least privilege, connector permissions, and environment boundaries. Data: Validate secrets isolation, log sanitization, DLP, and sensitive-data exclusions. Threats: Test prompt injection, tool misuse, data leakage, and unsafe output paths. Evidence: Maintain logs, audit trails, approval records, and vendor review evidence. Response: Define escalation and incident response for AI-specific failure modes.

Key takeaway

AI security is the security of connected data, tools, identities, logs, and decisions. Control the system, not just the prompt.
