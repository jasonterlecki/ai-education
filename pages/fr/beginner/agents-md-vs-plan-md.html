AGENTS.md ou PLAN.md

Ces deux fichiers peuvent sembler semblables parce qu’ils guident tous les deux le travail assisté par IA. Ils ont pourtant des rôles très différents. AGENTS.md est le livre de règles permanent du projet. PLAN.md est l’ordre de travail pour un changement précis.

La réponse utile la plus courte

AGENTS.md indique à un agent d’IA comment le projet doit être traité chaque fois. PLAN.md indique à l’agent quoi faire pour un travail précis.

AGENTS.md est la gouvernance. PLAN.md est l’exécution. L’un est la constitution de l’espace de travail. L’autre est le dossier de mission du jour.

Pourquoi les gens les mélangent

Les deux fichiers peuvent contenir des instructions, des étapes, des avertissements, et des contraintes. La différence se trouve dans la durée de vie et l’autorité. AGENTS.md devrait orienter chaque session. PLAN.md devrait guider un changement jusqu’à ce que ce changement soit terminé, remplacé, archivé, ou supprimé.

Si une règle devrait encore s’appliquer le mois prochain, elle appartient probablement à AGENTS.md. Si elle existe seulement pour terminer cette tâche, elle appartient probablement à PLAN.md.
AGENTS.md

Le livre de règles permanent

AGENTS.md est toujours présent et toujours pertinent. Il indique aux outils d’IA comment se comporter dans le projet avant de lire la tâche courante, de modifier des fichiers, d’exécuter des commandes, ou de proposer des changements.

  • Définit les règles, les limites, et la gouvernance à l’échelle du projet.
  • Explique ce que les agents ne doivent jamais faire.
  • Établit les attentes de validation, de tests, de révision, et d’approbation.
  • Décrit les modèles de commandes sécuritaires et les raccourcis interdits.
  • Devrait être durable, stable, et maintenu dans le temps.
PLAN.md

L’ordre de travail temporaire

PLAN.md existe pour mettre en œuvre quelque chose. Il découpe un changement précis en actions, phases, hypothèses, points d’arrêt, et vérifications de validation. Quand le travail est terminé, il peut être archivé, remplacé, ou supprimé.

  • Définit l’objectif et la portée d’une tâche ou d’un ensemble de changements.
  • Liste les actions, les phases, les points de contrôle, et les questions ouvertes.
  • Suit ce qui est terminé et ce qui doit encore être révisé.
  • Ne devrait pas contourner les règles permanentes de sécurité ou de gouvernance.
  • Peut disparaître une fois son travail terminé.

Pensez d’abord à la durée de vie

Pour décider où placer quelque chose, demandez combien de temps l’instruction devrait vivre. Le calendrier est souvent plus clair que le vocabulaire.

Permanent

Règles qui continuent de s’appliquer

Utilisez AGENTS.md pour les règles qui devraient guider chaque future session d’IA : limites de sécurité, points de révision, règles de style, politique de branches, attentes de validation, et approbation humaine requise.

Temporaire

Étapes pour ce changement

Utilisez PLAN.md pour le travail devant vous : quoi changer, dans quel ordre le faire, quels fichiers sont concernés, quelles questions restent ouvertes, et comment prouver que le changement fonctionne.

Pont

Les plans peuvent révéler de nouvelles règles

Parfois, un PLAN.md fait découvrir une règle récurrente. Quand cela arrive, déplacez la leçon durable dans AGENTS.md au lieu de la laisser enfouie dans un plan terminé.

Exemples courants

Voici le genre de lignes qui appartiennent à chaque fichier. Gardez les rails ennuyeux solides pour que le train créatif puisse aller plus vite.

AGENTS.md

Sécurité et permissions

« Ne jamais exposer de secrets. Ne pas committer d’identifiants. Ne pas exécuter de commandes destructrices sans approbation explicite. Les liens de navigation internes ne doivent pas ouvrir dans un nouvel onglet. »

AGENTS.md

Normes de validation

« Exécuter les tests pertinents. Exécuter git diff --check. Rapporter les fichiers modifiés, les résultats de validation, et toute vérification sautée avant de remettre le travail. »

AGENTS.md

Règles de style du projet

« Utiliser le français canadien pour les pages sous pages/fr/. Préserver les noms de fichiers en anglais. Garder les métadonnées de version dans les fichiers HTML gouvernés. »

PLAN.md

Étapes de tâche précises

« Traduire pages/en/beginner/example.html, mettre à jour l’élément correspondant dans la liste de vérification, vérifier lang=fr-CA, et confirmer que la navigation pointe vers les pages sœurs françaises attendues. »

PLAN.md

Phases de mise en œuvre

« Phase 1 : créer la page. Phase 2 : mettre à jour les liens d’index. Phase 3 : valider le HTML. Phase 4 : résumer les changements et les risques ouverts. »

PLAN.md

Questions ouvertes

« Confirmer si cette page appartient à débutant ou intermédiaire. Confirmer si la version française devrait pointer vers une future page suivante traduite. »

Bon usage et usage risqué

Le danger n’est pas d’avoir trop de fichiers Markdown. Le danger est de rendre le mauvais fichier autoritaire.

Bon usage

Gardez AGENTS.md assez court pour être respecté et assez fort pour compter. Utilisez PLAN.md pour rendre un travail concret, révisable, et facile à arrêter aux points de contrôle.

Usage risqué

Mettre des règles permanentes seulement dans PLAN.md, laisser des plans terminés prétendre être courants, ou laisser un plan de tâche contourner les règles de sécurité du projet parce qu’il est le fichier le plus récent.

Le cycle de vie

AGENTS.md et PLAN.md évoluent différemment dans le temps. L’un est une boussole maintenue. L’autre est une fiche d’itinéraire pour un trajet.

AGENTS.md

Créer une fois

Commencez avec les règles à l’échelle du projet, les valeurs par défaut sécuritaires, les attentes de validation, et les limites d’approbation humaine.

AGENTS.md

Maintenir durablement

Mettez-le à jour quand les règles durables du projet changent. Retirez les règles périmées avant qu’elles deviennent des fossiles décoratifs.

PLAN.md

Créer par effort

Écrivez un plan quand un changement nécessite des phases, des notes de risque, des étapes ordonnées, ou une validation explicite avant la mise en œuvre.

PLAN.md

Retirer quand terminé

Archivez-le si l’historique est utile. Supprimez-le s’il n’était qu’un échafaudage. Ramenez les leçons durables dans AGENTS.md.

Conclusion du guide de terrain : AGENTS.md est le fichier de gouvernance durable : toujours présent, toujours pertinent, et toujours utilisé pour orienter le comportement des agents. PLAN.md est le fichier temporaire de mise en œuvre : utile pour un changement, une phase, ou un lot de travail, puis archivé ou supprimé une fois le travail terminé. Si cela gouverne le projet, mettez-le dans AGENTS.md. Si cela dirige le travail du jour, mettez-le dans PLAN.md.
