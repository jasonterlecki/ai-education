Agent Handoff Notes

AI work often spans multiple sessions, people, tools, files, branches, approvals, and context windows. A handoff note keeps the thread alive when the agent, reviewer, or next human arrives later and needs to know what changed, what was proven, what is still uncertain, and where the little robot should absolutely not wander next.

Session continuity
Review evidence
Stop points

A handoff is not a diary. It is a control surface.

Good handoff notes let the next person resume work without rereading the entire chat scroll, guessing at hidden decisions, or trusting the agent’s confident little trumpet solo.

↻

They preserve state

The handoff captures the current project state: goal, scope, files touched, decisions made, evidence gathered, and unresolved questions.

It turns a vanishing chat into something the next session can safely inherit.

✓

They support review

A reviewer should know what changed, why it changed, what commands ran, what outputs mattered, and what still needs human judgment.

“It looks done” is not evidence. It is fog wearing shoes.

⏸

They enforce the stop

The best handoff tells the next agent where to continue, but also what not to touch, what not to assume, and what approval is required before the next rung.

The handoff loop

A handoff note is strongest when it follows the work from intent to evidence. The point is not to document every token sneeze. The point is to preserve the decisions that future work depends on.

GoalWhat the work was supposed to accomplish, in plain language.
ScopeWhat was in bounds, what was explicitly out of bounds, and which files or systems were protected.
ChangesWhat was created, edited, deleted, renamed, generated, or deliberately left alone.
EvidenceTests, diffs, screenshots, logs, commands, checks, review notes, or preview results.
RisksKnown gaps, assumptions, suspicious behavior, fragile areas, and decisions still requiring humans.
Next stepThe smallest safe follow-up, including the stop point before higher-impact work.

What belongs in a useful handoff?

The handoff should be small enough to read, but complete enough to prevent the next worker from having to excavate the chat ruins with a teaspoon.

1

Current objective

State the user’s actual goal, not a vague label. Include the accepted direction and any rejected alternatives that matter.

2

Boundary map

List allowed paths, forbidden paths, systems not touched, and any instruction like “do not update index.html.”

3

Change inventory

Include files created or modified, major sections added, commands used, generated artifacts, and visible outputs.

4

Validation evidence

Name what was checked: tests, syntax, file existence, preview, grep checks, screenshots, links, or review criteria.

5

Open loops

Call out uncertainty, missing inputs, untested areas, risky assumptions, and decisions waiting for a human owner.

Bad handoff vs. good handoff

A bad handoff sounds reassuring but does not transfer control. A good handoff lets the next worker act without guessing.

Weak handoff

Done. I made the page and fixed the footer. You can continue from here.

Useful handoff

Created /mnt/data/agent-handoff-notes.html. Did not modify index.html. Footer uses: <strong>Field guide takeaway</strong>: Validated: file exists, footer has no h2, title and meta level are present. Open item: page has not been added to site navigation yet. Next safe step: review page visually, then decide whether to update index.html in a separate approved change.

Different handoffs for different moments.

Not every handoff needs the same weight. A tiny content edit and a production-adjacent migration should not carry the same clipboard.

Handoff type Use when Must include Danger if omitted
Micro handoff Small draft, simple edit, single artifact, or short review pass. Goal, changed file, validation check, and next step. The next session repeats work or edits the wrong file.
Working handoff Multi-step task, several files, branch work, or a page that still needs review. Scope, changed files, decisions, checks run, open questions, and forbidden changes. The agent resumes from vibes instead of facts.
Review handoff Someone else must approve, merge, publish, deploy, or accept the result. Diff summary, risks, test evidence, screenshots or previews, and acceptance criteria. The reviewer approves a story instead of evidence.
Operational handoff Shared systems, external messages, production, infrastructure, customer data, or access control. Owner, exact actions, command list, environment, rollback path, monitoring, and stop conditions. Someone inherits an incident-shaped mystery box.

Handoff artifacts that travel well.

Handoffs can live in the chat, a markdown file, a pull request, a ticket, a runbook, or a release note. The right home depends on who needs to use it next.

MD

HANDOFF.md

Best for project state that another agent or human will use in a later session. Keep it short, current, and brutally practical.

PR

Pull request note

Best for review context: changed files, reasoning, test evidence, screenshots, risk notes, and areas requiring reviewer attention.

RUN

Runbook section

Best for operational continuity: commands, expected outputs, rollback triggers, monitoring checks, and approval points.

TKT

Ticket update

Best for team visibility: status, blockers, decisions, next owner, and what needs approval before progress continues.

LOG

Session log

Best for traceability: commands run, outputs observed, tool calls made, errors encountered, and corrective steps taken.

CHK

Checkpoint note

Best when work must stop between phases. It names the completed phase, evidence, unresolved risks, and the next approval gate.

Common handoff failures.

These are the little paper cuts that become debugging goblins two days later.

?

Missing boundary

The note says what was done, but not what was off-limits. The next agent may “helpfully” touch protected files.

∅

No evidence

The note claims success but includes no checks, diffs, preview, tests, or proof. That is not a handoff. That is glitter fog.

↯

Buried uncertainty

The agent hides assumptions in cheerful prose. Future work treats guesses as facts and the gremlin invoice arrives later.

∞

No stop condition

The next step is vague enough to become anything. A good handoff says exactly when to pause for human approval.

☍

Context soup

The handoff copies a giant chat instead of summarizing decisions, files, evidence, and blockers. Bulk is not clarity.

✕

Outdated note

The note survives after the state changed. Stale handoffs are worse than no handoff because they arrive wearing confidence perfume.

Reusable handoff prompt

Use this at the end of a session, before switching tools, before review, or whenever context is about to fall into the volcano.

Create an agent handoff note for the work completed so far. Include: 1. Objective: what the user wanted and the chosen direction. 2. Scope boundaries: what was allowed, what was forbidden, and anything explicitly not touched. 3. Files or artifacts created, changed, inspected, or intentionally left alone. 4. Key decisions made and rejected alternatives that matter. 5. Validation evidence: commands, checks, tests, previews, screenshots, links, or review observations. 6. Known risks, assumptions, missing inputs, and unresolved questions. 7. Current status: done, draft, blocked, needs review, or needs approval. 8. Next safest step and the exact stop point before any higher-impact action. 9. A short resume prompt the next agent can use to continue without guessing.
✓

Minimum viable handoff

Use this for small work:

Goal: Changed: Not touched: Validated: Open questions: Next safe step: Stop before:
★

Agent resume prompt

Use this when starting a fresh session:

Continue from the handoff below. Respect all listed boundaries. Do not assume missing context. Start by restating the current status, risks, and next safe step. Stop before any action marked as requiring approval.

Field guide takeaway: Agent handoff notes are the breadcrumb trail between context windows, people, tools, and approval gates. A good handoff does not merely say what happened; it preserves the objective, boundaries, files, decisions, evidence, risks, next safe step, and stop point so the next agent or human can continue from facts instead of reconstructing the work from glowing chat embers.
