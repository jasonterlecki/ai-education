Context Compression

Context compression is what happens when a conversation, document set, project history, or task trail becomes too large to carry in full. The AI, the tool, or the human operator has to squeeze the working record into a smaller shape. That squeeze can preserve the mission, or it can quietly turn the mission into soup.

Skill level: Intermediate Useful for long chats, agents, docs, and research Core habit: compress intentionally

The tiny suitcase problem

AI work often feels like you have a brilliant assistant with a tiny suitcase. You can give it a lot, but not everything forever. The important question is not whether context gets compressed. The question is who controls what survives.

1

Raw context

The full pile: chat history, uploaded files, requirements, constraints, examples, decisions, corrections, tool outputs, screenshots, and side comments. Raw context is rich, but bulky.

2

Compressed context

A smaller working memory that tries to preserve what matters: goals, constraints, decisions, accepted facts, open questions, current state, and warnings. Good compression is structured, not merely shorter.

3

Behavioral residue

The model may still carry a vague impression from earlier turns, even when details have faded. This is useful for tone, but dangerous for exact requirements, file paths, numbers, approvals, and legal or security boundaries.

1

Collect

Gather the working material: goal, constraints, source documents, current artifacts, known risks, and decisions already made.

2

Rank

Separate mission-critical facts from nice-to-have background. Not every detail deserves a first-class seat on the shuttle.

3

Distill

Rewrite the important material into compact, explicit statements. Preserve names, paths, dates, owners, and stop conditions.

4

Validate

Check whether the summary still supports the next task. Compression that cannot guide action is decoration with a clipboard.

5

Reload

Use the compressed brief as the new launch pad. Attach or cite the original sources when exact detail still matters.

What compression tends to lose

Compression does not usually fail by deleting the title. It fails by sanding off the weird little hooks that made the work safe, accurate, or yours.

Exceptions and negative requirements

“Do not touch production,” “exclude SQL-backed pages,” “do not change the footer structure,” and “only this folder” are exactly the kind of constraints that can vanish when a summary becomes too cheerful.

Decision history

The final plan may survive, but the rejected alternatives disappear. Later, the AI may propose the same discarded idea because it no longer knows why that road had bear traps.

Evidence quality

A compressed note may say “source says X” while dropping whether that source was official, outdated, partial, vendor marketing, or contradicted by another source.

Precise language

File names, policy wording, contract clauses, command flags, quoted user requirements, and approval language can be warped by paraphrase. Exact strings should be copied, not poetically rehydrated.

Ownership and approval gates

Summaries often keep the action but lose who approved it, who must review it, and where the task must stop. That turns a helper into a little bulldozer with a badge.

Tone and audience nuance

A useful style constraint such as “executive-friendly but not fluffy” or “beginner page, but not patronizing” can collapse into generic helpfulness unless it is preserved directly.

Lossless vs. lossy compression

Borrow the idea from files and images. Lossless compression preserves the original information exactly enough that it can be reconstructed. Lossy compression keeps a useful approximation and throws away detail. AI context compression is usually a mix of both, so you need to label which parts are exact and which parts are interpretation.

✓

Use lossless handling for hard facts

  • File paths, URLs, identifiers, account numbers, dates, versions, and command syntax.
  • Policy wording, requirements, legal language, safety rules, and exact acceptance criteria.
  • User instructions that limit scope, permission, tone, or deployment behavior.
≈

Use lossy handling for soft context

  • General background, brainstormed options, broad themes, and repeated explanations.
  • Style impressions, audience intent, and non-critical examples.
  • Earlier exploration that no longer controls the current decision.

Compression patterns that work

These patterns keep the useful signal alive when a project gets long enough to develop its own weather system.

A

The mission brief

Summarize the goal, audience, deliverable, current status, and next action in one compact block. This is the minimum viable map.

B

The decision ledger

Track decisions made, alternatives rejected, and why. This prevents the AI from digging up old zombies and calling them fresh strategy.

C

The constraint capsule

List non-negotiables separately from preferences. Put scope limits, permissions, formatting rules, and stop points where they cannot hide.

D

The source register

Preserve source names, freshness, authority, and what each source actually supports. Citation hygiene survives compression only if you pack it.

Compression is not memory.

A compressed summary is a deliberately shaped artifact. Memory is what the system may retain or retrieve. Context is what the model can currently use. Instructions are rules that guide behavior. Mixing those up creates a fog machine with a login screen.

Reusable prompt: compress this context safely

Use this when a thread has become long, before switching tools, before starting a new chat, or before asking an agent to continue work from prior discussion.

Compress the current context into a working brief for continuation.

Preserve the following separately:
1. Current goal and deliverable.
2. Exact file paths, names, commands, dates, versions, and identifiers.
3. Non-negotiable instructions and scope limits.
4. Decisions already made and rejected alternatives.
5. Open questions, risks, blockers, and approval gates.
6. Source evidence, including which claims each source supports and whether any source is stale, partial, or uncertain.
7. Current task state and the next recommended action.

Mark anything inferred as "inference".  Mark anything uncertain as "uncertain".  Do not smooth over contradictions.  Keep exact wording where precision matters.

Do

  • Ask for a compact brief before the conversation gets swampy.
  • Keep exact strings exact, especially paths, commands, quotes, and requirements.
  • Separate facts, decisions, assumptions, risks, and next actions.
  • Use bullets for compressed context, but keep the bullets specific.
  • Refresh from source documents when exactness matters.

Don’t

  • Trust “we discussed this earlier” as enough context for high-stakes work.
  • Let summaries replace source material for contracts, policies, security, money, or medical decisions.
  • Compress away negative instructions, rejected options, or human approval gates.
  • Assume a shorter summary is better. The best summary is the smallest one that still protects the work.
  • Let the AI invent continuity when a clean handoff is missing.

Field guide takeaway: Context compression is not just making a long chat shorter. It is deciding what must survive the squeeze: goals, constraints, exact facts, decisions, risks, evidence, owners, and stop points. Compress casually and the work comes back with missing bones. Compress deliberately and the next AI pass has a map, a compass, and fewer chances to wander into the glitter fog.
