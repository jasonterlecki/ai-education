Implementation Plans and Specs

Before asking AI to code or change real systems, create a plan that defines scope, constraints, phases, validation, rollout, rollback, and acceptance criteria.

Expertise: Intermediate Audience: Workflow owners and implementation leads Use when: A task needs controlled delivery Version: 1.0

Who this is for

This guide is for people who need to turn an AI-assisted idea into work that can be reviewed, assigned, implemented, tested, and rolled back.

What you will learn

  • When to create a PLAN.md, design brief, spec, migration plan, or runbook.
  • What a useful plan must include.
  • How plans reduce dangerous AI assumptions.

When a plan is required

Create a plan before AI-assisted implementation when the work touches real users, production behavior, data, permissions, workflows, integrations, infrastructure, migrations, security, or customer-facing communication.

A good plan does not need to be long. It needs to make the risky parts explicit before anyone starts changing files.

What the plan should cover

Scope

What is included, excluded, and unchanged.

Constraints

Rules, policies, file boundaries, and design limits.

Ownership

Who reviews, approves, deploys, and supports the work.

Phased execution

Small slices that can be implemented and reviewed.

Validation

Tests, linting, smoke checks, screenshots, or dry runs.

Rollout and rollback

How the change is released and how it is reversed.

Acceptance criteria

Observable conditions that prove the phase is done.

Good use and risky use

Good use

Ask AI to help draft a plan, then have humans review the scope, risks, validation, ownership, rollout, and rollback before implementation.

Risky use

Skip the plan because the prompt sounds clear, then let the AI infer architecture, permissions, migration steps, and acceptance criteria.

Try this prompt

Use this to prepare a plan before implementation.

Draft an implementation plan for: [change]. Include scope, out-of-scope items, constraints, ownership, phases, validation, rollout, rollback, acceptance criteria, and open questions. Do not write code. Flag any part that requires human approval before implementation.

Key takeaway

A plan is how you turn AI speed into controlled execution. It gives the agent boundaries and gives humans something concrete to review.
