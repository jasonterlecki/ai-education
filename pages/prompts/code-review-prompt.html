Code Review Prompt

AI can improve review coverage, but it does not replace accountable review.

Expertise: Advanced Category: Prompt Library Audience: Technical reviewers Use when: Reviewing a focused diff or code change Version: 1.0.1
Back to index Previous: Checkpointed Execution Next: Risk Review

Who this is for

This prompt is for technical reviewers who want AI to widen review coverage across correctness, security, tests, and maintainability.

What you will learn

  • How to focus AI review on concrete technical risks.
  • How to ask for likely findings, questions, false positives, and test gaps.
  • Why human review remains accountable.

When to use this

Use it with a focused diff, relevant context, and clear review criteria. It works best when the AI can see the changed behavior.

When not to use this

Do not paste secrets, customer data, private keys, credentials, sensitive logs, or confidential code into unapproved AI tools. Do not treat AI approval as human approval.

Good use and risky use

Good use

Use AI to widen review coverage, surface questions, and identify test gaps while reviewers verify findings against the actual diff.

Risky use

Accept AI review as approval, expose sensitive code or logs, or assume silence from AI means the change is safe.

Copy-ready prompt template

Code or diff review 
Review this code or diff.

Context:
[SYSTEM OR FEATURE CONTEXT]

Change goal:
[GOAL]

Diff or relevant code:
[PASTE APPROVED DIFF OR CODE]

Review for:
- correctness
- edge cases
- security issues
- maintainability
- test gaps
- performance issues
- unclear naming
- accidental behavior changes
- rollback concerns

Return:
1. High-confidence findings
2. Questions for the author
3. Possible false positives
4. Tests or checks to add
5. What a human reviewer must verify before approval
Security warning: Redact secrets, tokens, private keys, customer records, and sensitive logs. Use approved tools for private repositories and regulated data.

How to adapt it

Scope: Provide only the focused diff and relevant nearby context. Risk: Add known security, performance, or rollback concerns. Tests: Include expected validation commands or test files. Architecture: Tell AI about local patterns it must respect. Confidence: Ask it to separate likely issues from speculation. Ownership: Keep human reviewers responsible for approval.

Review before using the output

Evidence: Confirm findings tie to actual code or behavior. False positives: Do not act on speculative comments without checking. False negatives: Do not assume silence means safe. Tests: Add or run tests that match the risk. Security: Escalate sensitive issues to the right reviewers. Approval: Human reviewers make the final call.

Key takeaway

AI review is a useful second pass. It can surface issues, but accountable reviewers must verify and decide.
