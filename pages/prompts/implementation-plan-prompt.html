Implementation Plan Prompt

Use this when work affects real systems, users, data, workflows, security, permissions, production, migration, or support.

Expertise: Intermediate Category: Prompt Library Audience: Workflow and implementation owners Use when: Turning an idea into a reviewed plan Version: 1.0
Back to index Previous: Vibe Brief Next: Checkpointed Execution

Who this is for

This prompt is for people who need a structured plan before AI-assisted implementation, team delivery, or review-gated work begins.

When to use this

Use it when a change has meaningful blast radius, dependencies, data handling, rollout needs, or recovery requirements.

When not to use this

Do not use the resulting plan as automatic approval to code. The plan must be reviewed by accountable owners before implementation begins.

Copy-ready prompt template

Implementation plan 
Create an implementation plan for this work.

Goal:
[GOAL]

Context:
[CONTEXT]

Known constraints:
- [CONSTRAINT 1]
- [CONSTRAINT 2]

Include:
1. Scope
2. Assumptions
3. Non-goals
4. Proposed architecture or workflow
5. Affected files, components, teams, or systems
6. Phased execution plan
7. Validation commands or review steps
8. Rollout plan
9. Rollback plan
10. Risks and mitigations
11. Acceptance criteria

Separate what is known from what needs confirmation. Do not begin implementation.
Review gate: A plan is not permission to build. Review scope, risks, owners, validation, rollout, and rollback before implementation starts.

How to adapt it

Scope: Name what is included and excluded. Ownership: Add approvers, reviewers, and affected teams. Systems: Include known repositories, workflows, data stores, or vendors. Phases: Ask for small phases with stop points. Validation: Include tests, linting, dry runs, or manual checks. Recovery: Require rollback and stopping conditions.

Review before using the output

Completeness: Check scope, non-goals, affected systems, and assumptions. Controls: Confirm review gates match the risk. Validation: Ensure checks are specific and runnable. Rollout: Confirm sequencing, approvals, and communication. Rollback: Make sure recovery is practical before release. Acceptance: Define how done will be verified.

Key takeaway

Implementation planning turns an idea into reviewable work. It should reduce ambiguity before code, configuration, data, or workflow changes begin.
