Risk Review Prompt

Use this before applying AI output to systems with meaningful blast radius.

Expertise: Advanced Also useful for: Expert Category: Prompt Library Audience: Risk, security, and governance reviewers Version: 1.0
Back to index Previous: Code Review

Who this is for

This prompt is for reviewers assessing an AI proposal, implementation plan, automation, workflow change, or code change before it affects real systems.

When to use this

Use it when the change may affect users, data, permissions, operations, compliance, security, money, production, or public communication.

When not to use this

Do not use it as the only approval path for regulated, legal, security, HR, financial, medical, or high-impact decisions. Use official review processes.

Copy-ready prompt template

Risk review 
Review this AI proposal, plan, or code change for risk.

Change:
[SUMMARY]

Context:
[CONTEXT]

Affected systems or workflow:
[SYSTEMS / WORKFLOW]

Known constraints:
[CONSTRAINTS]

Identify:
- affected users
- affected systems
- data sensitivity
- permission changes
- security concerns
- operational risks
- compliance concerns
- rollback options
- monitoring needs
- approval gates
- reasons to stop

Return:
1. Risk summary
2. Highest-risk assumptions
3. Required review gates
4. Validation and monitoring needed
5. Rollback or stop conditions
6. Recommendation: proceed, revise, escalate, or stop
Escalation rule: AI can help identify risks, but official risk, security, privacy, legal, compliance, and operational owners must review high-impact work.

How to adapt it

Blast radius: Name users, systems, environments, and data that could be affected. Data: Include classification and privacy constraints without exposing sensitive records. Permissions: Call out identity, IAM, roles, connector access, or approval changes. Operations: Include deployment, support, monitoring, and incident response context. Rollback: Ask for reversible steps and stop conditions. Approval: Map risks to required reviewers.

Review before using the output

Coverage: Check users, systems, data, permissions, operations, and compliance. Severity: Confirm the risk level is not understated. Evidence: Verify assumptions against source material. Controls: Confirm gates, monitoring, rollback, and stop conditions. Escalation: Route high-risk items to accountable owners. Decision: Record whether to proceed, revise, escalate, or stop.

Key takeaway

Risk review is a control point. Use AI to widen the questions, then use human accountability to decide what happens next.
